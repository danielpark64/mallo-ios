## 1. 업로드 키 만들기 (한 번만, 직접)

비밀번호를 직접 정해야 해서 이 단계는 대신 할 수 없습니다.

```bash
keytool -genkeypair -v -keystore android/app/release.jks -alias sayram-upload -keyalg RSA -keysize 2048 -validity 10000
```

그다음 `store-assets/keystore.properties.example`을 `android/keystore.properties`로 복사해 방금 정한 비밀번호를 채웁니다.

- `release.jks`와 `keystore.properties`는 커밋되지 않습니다. **두 파일과 비밀번호를 따로 안전한 곳에 보관**하세요.
- Play 앱 서명을 쓰므로 업로드 키를 잃어버려도 Google에 재설정을 요청할 수 있습니다.
- `keystore.properties`가 없으면 debug 키로 서명됩니다. 그 파일은 Play에 올릴 수 없습니다.

## 3. 업로드 파일(AAB) 만들기

1번을 마친 뒤에 만듭니다.

```bash
find node_modules ios android modules -name "* [0-9].*" -delete
```

```bash
cd android && ./gradlew bundleRelease
```

결과 파일 `android/app/build/outputs/bundle/release/app-release.aab`를 `~/Desktop/세이람-1.0.0-vc1.aab`로 복사해 올립니다.

- 첫 줄은 iCloud가 만드는 중복 파일(`이름 2.java` 등)을 지우는 것입니다. 안 지우면 빌드가 실패합니다.
- 2026-10-13에 debug 서명으로 빌드가 되는 것까지 확인했습니다(52MB, 패키지 `com.danielpark.sayram`).
- versionCode 규칙: 한 번 올린 번호는 출시하지 않았어도 다시 못 씁니다. 올린 뒤 코드를 고쳤다면 versionName은 두고 versionCode만 올립니다(`app.json`의 `android.versionCode`와 `android/app/build.gradle`).
- 심사 중에는 다시 제출하지 않습니다(대기 순서가 처음부터 다시 시작).

### 광고를 "예"로 답하는 이유

일정 목록 맨 아래에 홍보 배너가 있습니다(수수뮤직 채널, 교대알람, 개발자 응원하기). 외부 광고 SDK는 아니지만, Google은 **자기 앱·제품을 알리는 배너도 광고로 보고 "예"로 신고**하라고 안내합니다. "아니요"가 허용되는 것은 메뉴 안의 "다른 앱 더 보기" 같은 링크뿐입니다. 사실과 다르게 신고하면 정책 위반으로 앱이 정지될 수 있습니다.

- "예"로 답하면 스토어 페이지에 "광고 포함" 표시가 붙습니다.
- 그래서 등록 문구에는 "광고 없음"이라고 쓰지 않았습니다. 대신 사실인 "광고 추적 없음(광고 네트워크 없음)"을 적었습니다.
- 표시를 붙이고 싶지 않으면 배너를 빼야 합니다. `lib/promo.ts`의 `promoSlides`가 빈 목록을 돌려주면 배너가 사라집니다. 그 경우 등록 문구도 "광고 없음"으로 되돌릴 수 있습니다.
- 교대알람도 같은 배너가 있으니 같은 기준이 적용됩니다. 그 앱의 광고 신고와 등록 문구("광고 없음")를 확인해 보는 것이 좋습니다.

### 후원 안내(개발자 응원하기)에 대한 주의

한국어 화면에서만 보이는 "개발자 응원하기"는 계좌번호를 보여 주는 화면입니다. Google의 결제 정책에서 Play 결제를 쓰지 않아도 되는 기부는 **비과세 단체에 대한 기부**로 한정돼 있고, 개발자 개인에게 보내는 후원 링크 때문에 삭제 요구를 받은 앱 사례(AnkiDroid, Mycelium)가 있습니다. 계좌 이체 안내가 여기에 해당하는지는 공식 문서로 확인하지 못했습니다.

- **결정(2026-10-14): 후원 슬라이드를 넣은 채로 올립니다.** 같은 화면이 들어 있는 교대알람이 심사를 문제없이 통과했기 때문입니다.
- 그래도 심사에서 지적되면 `lib/promo.ts`에서 `coffee` 슬라이드 한 줄만 빼고 versionCode를 올려 다시 제출하면 됩니다.

## 6. 데이터 보안 양식

- **"앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요?" → 아니요.**
- 근거: 앱에 인터넷 권한이 없어 어떤 데이터도 기기 밖으로 보낼 수 없습니다(최종 빌드의 권한 목록으로 확인). 녹음·일정은 앱 전용 저장소에만 있습니다. 광고 SDK·분석 SDK가 없습니다. 홍보 배너는 앱 안의 글과 그림뿐이고, 누르면 브라우저나 YouTube·Play 앱이 대신 열립니다.
- 참고: 음성을 글로 바꾸는 일은 기기의 음성 인식 서비스(Google 음성 서비스 등)가 하며, 개인정보처리방침 2항에 적었습니다. Google의 정의상 "수집"은 앱과 앱에 포함된 SDK가 기기 밖으로 전송하는 것을 말하므로 이 앱의 수집에는 해당하지 않는다고 판단했습니다. 더 보수적으로 가려면 "오디오 › 음성 또는 사운드 녹음: 수집됨, 일시적으로 처리, 앱 기능 목적, 공유 안 함"으로 신고할 수도 있습니다. **법적 신고이므로 최종 선택은 직접 해주세요.**
- 나중에 인터넷 권한이나 광고 SDK를 넣으면 이 양식, 등록 문구의 "인터넷 권한 없음" 문단, 개인정보처리방침을 함께 고쳐야 합니다.

## 7. 권한 신고

빌드에 들어간 권한: 마이크, 알림, 정확한 알람(USE_EXACT_ALARM/SCHEDULE_EXACT_ALARM), 전체 화면 인텐트, 포그라운드 서비스(미디어 재생), 다른 앱 위에 표시, 부팅 시 시작, 진동, 화면 깨우기, 오디오 설정 변경. 인터넷 권한은 없습니다.

| 신고 | 적을 내용 |
|---|---|
| 정확한 알람 (USE_EXACT_ALARM) | 핵심 기능이 "캘린더·알람": 사용자가 말로 정한 일정 시각에 알람을 울리는 앱입니다. 사용자가 지정한 시각에 정확히 울려야 합니다. |
| 전체 화면 인텐트 | 알람이 울릴 때 잠금 화면 위에 알람 끄기 화면을 보여주기 위함(알람 앱 용도). |
| 포그라운드 서비스 – 미디어 재생 | 알람이 울리는 동안 알람 소리를 재생하고, 사용자가 "끄기"를 누르면 즉시 종료합니다. 시연 영상이 필요하면 알람이 울리고 끄는 장면을 짧게 찍어 링크합니다. |

교대알람과 같은 권한 구성이라 그때 통과한 설명을 그대로 쓰면 됩니다.

## 14. 알려진 경미한 문제 (출시를 막지 않음)

- 설정에서 테마를 바꾼 직후 상태 표시줄 아이콘 색이 잠깐 안 맞음(설정을 닫았다 열면 정상)
- 일부 알림창 버튼이 한국어에서도 "OK"
- 알람 울림 화면의 시각이 24시간제("18:20")
- Android에서 "5분 후 다시"를 누른 뒤 5분 안에 앱을 완전히 껐다 켜면 미룬 알람이 사라질 수 있음(코드로만 확인, 실기기 재현 필요)
