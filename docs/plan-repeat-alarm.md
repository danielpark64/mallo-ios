# 기획안 — 반복 일정·알람 (매년·매월·매주) (2026-11-28 초안)

단계: **기획**(코드 없음). 사용자 승낙 → 시안 → 개발 순서.
알람 로직은 교대알람이 원본이다(맞춤표 1번). 그래서 개발 전에 관리 창과 맞출 곳을 먼저 정한다(아래 6번).

## 1. 왜
- 지금 세이람에는 반복이 전혀 없다. 생일·기념일·월세·매주 수업처럼 되풀이되는 일은 매번 새로 넣어야 한다.
- "엄마 생일 3월 5일 매년", "매달 25일 월세", "매주 월요일 9시 회의"처럼 **말로 한 번 하면 끝**이 되면 '말로 일정'이라는 세이람 성격과 잘 맞는다.

## 2. 넣을 반복 종류

| 종류 | 예 | 세부 선택 |
|---|---|---|
| 매주 | 매주 월·수 9시 | 요일 여러 개 |
| 격주 등 | 2주마다 토요일 | 간격(2·3·4) — 2단계 |
| 매월 | 매달 25일 / 매달 마지막 날 / 매달 셋째 주 금요일 | 날짜 또는 'N번째 무슨 요일' |
| 매년 | 생일 3월 5일 | **양력 / 음력** 선택 |
| 끝 | 없음 / 날짜까지 / N번 | 기본은 '끝 없음' |

빼는 것: 시간 단위 반복(매시간), 사용자 지정 규칙 편집기. 복잡하고 쓰는 사람이 적다.

## 3. 쓰는 모습
- **말로**: 파서가 '매주 ○요일·매달 ○일·매년·해마다·음력' 같은 말을 알아듣는다. 9개 언어 모두("every year", "毎年", "每年"…). 날짜를 말하지 않으면 다음에 오는 날로 정한다.
- **편집 화면**: 알람 칸 아래에 '반복' 한 줄을 넣는다. **순서는 안 함 · 매년 · 매월 · 매주**(2026-11-28 사용자 결정 — 눈에 띄는 앞쪽에 매년·매월, 매주는 맨 뒤, 매일은 넣지 않음). 고르면 세부 선택이 펼쳐진다. 생일이면 '음력' 스위치.
- **달력**: 반복 일정은 해당하는 날마다 보이고, 작은 반복 표시(↻)를 단다.
- **목록**: 한 줄만 보이고 '다음: 3월 5일'로 표시한다.
- **한 번만 바꾸기**: 반복 일정의 그날만 미루기·결과 표시·삭제를 할 때 '이번만 / 앞으로 전부'를 묻는다(구글·애플 캘린더와 같은 방식).
- **생일 편의**: 매년 일정에 '하루 전 미리 알림'을 기본으로 켜 두는 것을 제안한다(설정의 기본 미리 알림과 별개).

## 4. 알람은 어떻게 거나 (핵심 위험)
세이람은 늘 가볍게 간다. 백그라운드 타이머나 폴링을 쓰지 않으므로 **'다음 몇 번만 미리 건다'** 방식으로 한다.
- 앱을 열 때, 재동기화 때, 알람이 울리거나 꺼질 때마다 각 반복 일정의 **다음 발생 몇 개**만 계산해 건다. 지금 쓰는 scheduleAlarm·resyncAlarms를 그대로 쓴다.
- 몇 개를 거나:
  - 매년·매월은 2~3번(몇 년, 몇 달 앞까지 덮음)
  - 매주는 iOS Expo 64개 한도 안에서 나눠 쓴다
  - iOS 26+ AlarmKit은 한도가 없다. 매주는 교대알람처럼 AlarmKit 요일 반복(.relative weekly) 한 건으로 걸 수 있다. 이때 교대알람 45번 요일 변환 버그 수정본을 그대로 가져온다.
- **앱을 오래 안 열 때**:
  - 매주 반복(요일이 많을 때)은 iOS Expo 방식에서 대략 2~3주 뒤에 끊길 수 있다.
  - 해결: AlarmKit 반복, Expo의 매주 반복 트리거, Android 네이티브 AlarmManager를 울린 뒤 다음 것을 스스로 다시 거는 방식으로 고치기.
  - 어느 것을 쓸지는 교대알람 방식에 맞춘다.
- Android는 두 경로(Expo + 네이티브 AlarmManager)를 모두 처리하고, 진입점은 lib/notifications.ts만 쓴다.

## 5. 데이터·다른 기능에 미치는 것
- 일정에 `repeat` 칸을 더한다(종류, 간격, 요일, 몇 번째 주, 음력 여부, 끝). 그날만 바꾼 것은 `exceptions`(날짜별 미루기·결과·삭제)로 둔다. 예전 일정은 `repeat`이 없으니 그대로 동작한다.
- 계산은 순수 함수 하나(`lib/repeat.ts`: 다음 발생 N개)로 모으고 jest로 고정한다. 함정이 있는 날짜도 시험에 넣는다:
  - 2월 29일 → 평년엔 28일
  - 31일 → 짧은 달엔 마지막 날
  - 음력 윤달
  - 서머타임이 있는 나라
- **음력**: 지금은 양력을 음력 표시로 바꾸는 것만 있다. 음력 날짜를 양력으로 바꾸는 계산을 새로 넣어야 한다. 기기 달력 기능으로 그해 날짜를 훑는 방식이면 인터넷 없이 된다.
- **일정 보내기**: 링크에 반복 정보를 더한다. 예전 앱은 모르는 칸을 무시하므로 '한 번짜리'로 받는다.
- **위젯·결과 표시·미루기·검색·내보내기(ICS)**: '다음 발생' 기준으로 맞춘다. ICS 내보내기는 RRULE로 쓴다.
- 9개 언어: 문구가 추가된다(i18nParity 시험이 누락을 잡는다).

## 6. 교대알람과 맞출 것(관리와 먼저 정함)
- 교대알람에는 요일 반복과 근무 패턴 반복이 이미 있다. 반복 계산과 알람 예약 방식을 교대알람 것을 가져다 쓸지, 세이람에서 새로 만들어 교대알람이 가져갈지는 관리 창이 정한다.
- AlarmKit 요일 반복, 45번 수정본, 진동만 AlarmKit(44번)은 교대알람 코드를 그대로 쓴다.

## 7. 범위(2026-11-28 사용자 결정)
- **넣는 것**: 매년(양력·음력) · 매월 · 매주(요일 여러 개 — 평일 매일이 필요하면 월~금을 고르면 됨) · 격주 · N번째 요일 · 끝 조건.
- **매일은 넣지 않는다**(2026-11-28 사용자): 휴대폰 기본 시계로 충분하고, 64개 한도 부담이 가장 큰 종류라서.
- **보이는 순서**: 매년·매월을 앞에 두고, 매주는 맨 뒤에 둔다. 도움말·스토어 문구에도 '생일·기념일·매달 내는 돈'을 앞세운다.
- 매주는 교대알람의 요일 반복 로직(AlarmKit weekly, 45번 수정본 포함)을 가져와 쓴다(6번). 교대알람을 따로 권하지는 않는다 — 교대 근무자용 앱이라서.
- 순서: 시안 승낙 → 개발 → 실기기 시험(진동만) → 양쪽 같은 버전 출시. 1.2.5(알람 수정)를 올린 뒤 시작한다.

## 8. 정할 것(사용자)
- 음력 매년을 한국어 외 언어에서도 보이게 할지(중국어·베트남 등 음력을 쓰는 곳이 있음).
- 반복 일정의 그날만 바꿀 때 '이번만 / 앞으로 전부'를 묻는 방식이 괜찮은가.
