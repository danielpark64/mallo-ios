# 홈 화면 위젯 계획 (1.1.0, 2026-11-08 확정)

## 결정한 것
- iOS·Android 위젯 화면은 **따로** 만든다(iOS WidgetKit·SwiftUI / Android AppWidget·Kotlin).
  보여 줄 내용은 앱(JS)이 한 번 골라 **작은 요약 파일**로 쓰고, 두 위젯은 그 파일만 읽어 그린다.
  위젯이 records.json·녹음을 직접 읽지 않는다(가볍게).
- 출시: 첨부 기능과 함께 **1.1.0**. Android는 프로덕션 통과 뒤 첫 업데이트, iOS도 같은 때.

## 크기별 모양
| 크기 | 내용 |
|---|---|
| 작게 (2×2) | 바로 다음 일정 1개(날짜·시각·이름), 같은 날 더 있으면 "외 N건" |
| 중간 (4×2) | 다가오는 일정 4개 + 마이크 버튼(누르면 앱이 열리며 바로 말하기) |
| 크게 (4×4) | 위: 이번 달 달력(날짜 아래 **근무 첫 글자** + 일정 있는 날 파란 점, 오늘 빨간 원) · 오른쪽 위 마이크<br>아래: 다가오는 일정(오늘부터 30일) 3개 |

- 큰 위젯 아래 목록 넘기기: **Android는 손가락 스크롤**, **iOS는 ▲▼ 버튼 + "1/3" 쪽 표시**(iOS 17+ 인터랙티브 위젯, 17 미만은 첫 3개만).
- 6주짜리 달은 목록 2개, 근무표가 없으면 점만 나오고 목록 4개.
- 근무 이름은 첫 글자. 첫 글자가 겹치는 근무(휴무·휴가 등) 처리는 구현 때 확인.
- 날짜를 누르면 앱의 그날, 일정을 누르면 그 일정 상세가 열린다.
- 기간 일정은 파란 글씨.

## 갱신
- **원본이 바뀌면 즉시**: 일정 추가·수정·삭제, 알림의 미루기, 백업 복원, 근무표 변경 — 모두 저장 함수 한 곳에서 요약 파일을 쓰고 위젯 다시 그리기를 부른다.
- **시간이 지나면 그 시각에**: 자정(오늘 표시·달 바뀜), 각 일정 시각(지난 일정 빠짐) — iOS는 타임라인 항목, Android는 그 시각에 한 번 갱신 예약. 주기적 폴링은 하지 않는다.
- iOS는 App Group `group.com.danielpark.shared`(이미 설정됨)에 요약 파일을 둔다.

## 순서
1. 공통 요약 파일(JS) + 저장 경로에 갱신 연결
2. Android 위젯 3종 → 노트에서 확인
3. iOS 위젯 확장 3종 → 아이폰에서 확인
4. 9개 언어 문구, verify-fix, 기기 확인 후 커밋
