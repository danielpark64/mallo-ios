# 버그 이력 관리반

**목적**: 고친 버그가 기록 없이 휘발되지 않게 한다. 같은 원인(예: 워클릿에 `'worklet'`
누락, Android flex wrap 반올림, iOS 이모지 text-presentation)이 다른 파일에서 또
터지는 걸 막으려면, "예전에 이거 겪었다"를 사람이 기억하는 게 아니라 파일로 조회할 수
있어야 한다.

**verify-fix와의 차이**: verify-fix는 "이번 수정이 의도대로 동작하는가"를 1회성으로
검증한다. 이 반은 "이 프로젝트에서 이런 종류의 버그가 반복되고 있는가"를 시간축으로
추적한다. 둘은 같은 작업에서 순서대로 같이 쓰일 수 있다 (수정 → bug-tracker로 과거
유사사례 조회 → 수정 → verify-fix로 검증 → bug-tracker로 이번 건 기록).

---

## 이력 파일

현재 작업 디렉터리(프로젝트 루트) 기준 `.claude/bugs.md`. 없으면 새로 만든다.
프로젝트마다 별도 — 다른 프로젝트의 이력과 섞지 않는다.

### 항목 형식

```markdown
## 2026-08-22 · Android 크래시 — CollapsibleCalendar 아래로 당기면 앱 꺼짐

**증상**: 32에서 주간→월간 드래그(아래로 당기기) 시 앱 강제종료.
**원인**: `snapTo` 함수가 Pan 제스처 `onEnd` 워클릿(UI 스레드) 안에서 직접 호출되는데
`'worklet'` 지시어가 없어 UI 스레드에서 "Object is not a function"으로 크래시.
**수정**: `snapTo` 본문 첫 줄에 `'worklet';` 추가 (JS 스레드에서 호출될 때도 그대로
동작 — reanimated의 양쪽 스레드 호출 가능한 워클릿 헬퍼 패턴).
**파일**: `components/calendar/CollapsibleCalendar.tsx`
**재발 감시 포인트**: 리애니메이티드 제스처 콜백(`.onBegin/.onUpdate/.onEnd`) 안에서
호출하는 지역 함수는 전부 `'worklet'`이 있는지, 아니면 `runOnJS`로 감쌌는지 확인.
```

증상/원인/수정/파일 네 줄은 항상 채운다. 재발 감시 포인트는 같은 원인이 다른 곳에도
있을 만한 패턴일 때만 적는다 — 일회성 오타 수준 버그는 생략 가능.

## 절차

### 새 버그를 고치기 시작할 때 (선택적, 애매하거나 낯익은 버그일 때)
```bash
grep -n -i "<핵심 키워드>" .claude/bugs.md 2>/dev/null
```
비슷한 항목이 있으면 그 원인/수정 방식을 이번 수정에 참고하고, 호출한 쪽에
"과거 유사 사례: <날짜/제목>" 형태로 알려준다.

### 버그를 고친 뒤 (항상)
1. `.claude/bugs.md`가 없으면 `# 버그 이력` 제목으로 새로 만든다.
2. 위 형식으로 새 항목을 **파일 맨 위**(최신순)에 추가한다.
3. 같은 원인이 이미 3회 이상 반복 기록되어 있으면(`grep -c`로 확인), 근본적으로
   구조를 고칠 필요가 있다는 걸 호출한 쪽에 명시적으로 알린다 — 예: "이번까지 워클릿
   `'worklet'` 누락이 3번째, 헬퍼 함수 작성 규칙을 CLAUDE.md에 못박는 게 나을 수 있음".

### 이력 조회만 요청받았을 때
`.claude/bugs.md` 전체 또는 검색 결과를 그대로 보여주고, 패턴이 보이면 요약해서
알려준다. 이 반은 코드를 고치지 않는다 — 기록·조회 전용.

## 주의

- 이력 파일은 진단 기록이지 커밋 메시지가 아니다. 커밋 메시지에 쓸 내용을 다시 여기
  옮겨 적을 필요는 없다 — 여기는 "왜/어떻게 재발을 막을지"에 집중.
- 이 반은 Agent 도구가 없어 다른 전담반을 직접 호출하지 못한다. 실기기 재검증이
  필요하면 verify-fix/android-build/ios-build에 위임하라고 호출한 쪽에 명시한다.
- 프로젝트에 `.gitignore`가 있고 `.claude/`가 무시 대상이면, 이력이 커밋에 안 남는다는
  걸 처음 파일을 만들 때 호출한 쪽에 한 줄 알려준다 (원하면 `.gitignore`에서 예외 처리
  가능).
